# 能力建议草稿（尚未提交）

目标：小黑盒小程序工坊 SDK 私有反馈工单。未经用户同意不发送。

SDK：0.9.1。目标：小黑盒内置小程序，重点 iOS；具体客户端版本未读取。本地环境 Windows，React / TypeScript。

用例：游戏双模式云排行榜需要展示玩家当前的小黑盒头像和昵称，包含已经上榜的玩家。

已核对 2026-10-19 官方 Markdown 文档：LeaderboardEntry 只有 appUserId、score、extra、rank、ranked、createdAt、updatedAt；user.getInfo 只返回当前用户已授权资料。submit 同分或更差时不更新 extra。

当前做法：新增 userInfo，当前用户资料用于本人展示；将昵称和头像快照放入新纪录 extra，供其他玩家读取。资料仅作展示，不参与身份校验。历史玩家没有快照时使用占位显示。

限制：无法给他人历史成绩补齐资料；改名、换头像后需要更高分才能更新公开快照。删除重传会改变成绩持久状态和同分先后，不应作为更新资料的手段。

期望：提供受平台控制的可选展示资料字段（遵守披露授权）或单独的公开展示资料查询能力，避免页面自行持久化个人资料。如暂不能提供，建议提供不会改变 score / 排序时间的当前用户展示资料更新能力。

这属于公开能力不足，尚无证据表明 SDK 实现有缺陷。未附用户 ID、昵称、头像 URL、凭据或完整日志。真机新版本回归待进行，不宣称线上修复完成。
